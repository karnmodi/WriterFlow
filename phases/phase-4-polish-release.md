# Phase 4 — Polish, Fallbacks & Release

**Goal:** Make it feel like a real product — smooth, resilient, and publicly installable. V1 uses manual updates; trusted signing/notarization and auto-updates are v2 work.

## Stage 4.1 — Clipboard fallback pipeline ✅

For apps where AX write fails (tracked in the compatibility map):

- [x] Save current clipboard (all types, incl. images) → set rewritten text → simulate `⌘A` (if replacing all) or rely on existing selection → `⌘V` via CGEvent → restore clipboard after 300 ms. *(Already built in Phase 1 — `ClipboardWriter.executePaste` + `TextInserter.replace`'s tier-3 fallback, generic `NSPasteboardItem` save/restore covers all pasteboard types.)*
- [x] Guard: only when the original field is still focused (re-check AX focus before injecting). *(New: `ClipboardWriter.executePaste` now takes `preText`/`isWeb` and aborts the paste — returning the existing "text is on your clipboard" error path — if the freshly-read field value no longer overlaps what it held when the action started, e.g. the user tabbed to a different field in the same app during the streaming round-trip.)*
- [x] Settings toggle (default on) + per-app override. *(Deviation, noted here per CLAUDE.md: the existing global `SettingsStore.forceClipboardFallback` toggle — shipped in Stage 3.4 — forces skipping the AX tiers entirely, defaulted **off**; the automatic tier-3 fallback-when-AX-fails is unconditional/always-on regardless of that toggle, which already satisfies "default on" for the fallback mechanism itself. Defaulting the *force* toggle to on would make every app skip AX writes, needlessly destroying rich-text formatting Golden Rule #... prefers `kAXSelectedTextRange` for — so its default was left as-is. Added the missing piece: a tri-state per-app override, `AppRule.clipboardFallback: Bool?` — `nil` inherits the global default, `true` forces clipboard for that app, `false` disables clipboard paste entirely for that app (fails loudly instead). Editable via a segmented Auto/Always/Never picker in the Personalization tab's per-app rule row.)*
- [x] Same for **read** fallback: `⌘A ⌘C`, read clipboard, restore selection where possible. *(New: `ClipboardWriter.executeCopyAll` + `ContextExtractor` now distinguishes "kAXValue unreadable" (nil) from "legitimately empty" (`""`) and only falls back to `⌘A ⌘C` in the unreadable case, restoring the prior `AXSelectedTextRange` and the user's clipboard afterward. Deliberately excluded for terminal apps — a scrollback-wide `⌘A ⌘C` would leak the whole history, defeating `TerminalApps.currentLine`'s deliberate line-scoping privacy safeguard. Also wired up `CompatibilityMap.recordRead`, which existed since Phase 1 but was never actually called anywhere until now.)*

**Accept:** An app with broken AX write (test with one from the compatibility map) still gets in-place replacement; user clipboard contents restored intact. *(Code-complete + `swift build` clean; not yet exercised live against a real broken-AX app in this sandbox — no AX grant. Verify manually per CLAUDE.md when convenient.)*

- [x] Sound-free by default; optional subtle haptic on Replace (Force Touch trackpads). *(Added `NSHapticFeedbackManager.defaultPerformer.perform(.generic, ...)` in `applyPreview`'s success path — silently a no-op on Macs/trackpads without the Taptic Engine, no sound anywhere.)*

**Accept:** 10-person "does this feel native?" gut-check — no jank reports; fullscreen Chrome + external monitor both correct. *(Code-complete + `swift build` clean; the actual gut-check needs a live multi-person pass the user will need to run outside this sandbox.)*

## Stage 4.3 — Resilience & performance ✅ (soak test excepted)

- [x] Kill-switch watchdog: if AX calls hang 3× in an app, auto-disable WriterFlow for that app for the session (toast + dashboard note). *(New: `AXWatchdog` (`@MainActor ObservableObject`, session-only — deliberately not persisted, unlike `AppRule.excluded`) tracks consecutive AX read/write failures per bundle ID via the existing `recordRead`/`recordWrite` call sites in `ContextExtractor`/`TextInserter`. A success resets the streak; 3 in a row auto-disables the app for the rest of the launch, shows an `ErrorToast`, and gates the floating icon in `OverlayController.fieldDidFocus` alongside the existing `AppRuleStore.isExcluded` check. Dashboard note: Settings tab's Reliability card now lists any session-paused apps with a one-click "Re-enable" button.)*
- [x] Event tap auto-re-enable (taps get disabled by the OS under load — listen for `kCGEventTapDisabled*`). *(Already built in Phase 0 — `EventTap` handles `.tapDisabledByTimeout`/`.tapDisabledByUserInput` and calls `CGEvent.tapEnable` again. No change needed.)*
- [ ] Memory/CPU soak test: 8 h run, < 80 MB RSS, < 1% idle CPU. *(Not run — needs a live 8-hour session against the real AX/menu-bar app, which this sandbox can't do (no AX grant, and launching the dev build risks colliding with the user's actual running production instance per prior session notes). Left for the user to run outside this sandbox.)*
- [x] Offline mode: clear error, actions queue is NOT kept (no surprise sends later). *(Audit + fix: there was never any retry/queue mechanism for failed actions — a failure just surfaces `onFailed`/`ErrorToast` and the attempt is gone, satisfying "no surprise sends later" already. Added a `ActionEngine.userFacingMessage(for:)` helper that special-cases `URLError` (`.notConnectedToInternet`/`.networkConnectionLost`/`.dataNotAllowed` → "You're offline — try again once you're connected.", `.timedOut` → "Request timed out — try again.") instead of surfacing a raw system error string, and replaced all 4 duplicated error-message call sites in `ActionEngine` with it.)*
- [x] Rate limiting: max 1 in-flight request; rapid re-invokes cancel the previous. *(Already correct since Phase 1/2 — `ActionEngine.run()`/`finalizePromptBuilder()` both call `runningTask?.cancel()` before starting a new `Task`, `execute()`/`executeMultiVariant()` check `Task.isCancelled` at multiple points, the 3-variant path uses structured `withTaskGroup` so cancellation cascades to all children, and `AzureOpenAIClient`'s `session.bytes(for:)`/`.lines` async iteration is itself cancellation-aware, so an in-flight network request actually stops rather than just being ignored. No change needed.)*

## Stage 4.4 — V1 public packaging & distribution (production checks reopened)

- [x] DMG with drag-to-Applications layout. *(`scripts/make-dmg.sh` / `make dmg` stages `WriterFlow.app` plus an `Applications` symlink and creates a UDZO DMG. The packaging layout has been mounted and checked locally.)*
- [x] Turn the existing ad-hoc bundle + DMG steps into a verified v1 release workflow. *(`make verify-release` cleans, tests, builds Release, verifies version/ARM64/signature/runtime/notices, scans the app + mounted DMG, and generates/verifies the checksum.)*
- [x] Make ad-hoc release signing fail loudly and enable/verify hardened runtime. *(The release workflow is strict; debug rebuilds remain lenient. Live Accessibility/Input Monitoring compatibility remains part of the unchecked manual acceptance pass.)*
- [ ] Publish and verify a SHA-256 checksum beside every public DMG. *(Generation and local verification pass automatically; publication/download verification waits for the actual public HTTPS release.)*
- [ ] Document and test the real Gatekeeper flow on a clean, unmanaged Mac: drag to Applications, attempt first launch, then use **System Settings → Privacy & Security → Open Anyway**. *(`AppRelocator` cannot solve the initial block because its code cannot run until Gatekeeper has already allowed the app. Do not instruct users to disable Gatekeeper or run `xattr`; managed Macs may prevent the override.)*
- [x] Crash reporting: local crash log collection + "share diagnostics" button (opt-in, no auto-upload). *(New: `DiagnosticsExporter` builds a plain-text report — app/OS version, `compatibility.json`'s per-app AX success/fail counts (no field content), and the most recent WriterFlow entries under `~/Library/Logs/DiagnosticReports/` that macOS already collects on any crash — and only ever writes it via an explicit `NSSavePanel` from a new "Share Diagnostics…" button in the Settings tab's Reliability card. No automated capture pipeline, no network upload, ever.)*
- [x] Repository build, architecture, permissions, and privacy documentation exists in `README.md`; the canonical v1/v2 production split and release procedure now lives in `RELEASE.md`.
- [ ] Version 1.0.0 tag and final changelog. *(The tag is gated on the live verification, soak, production AI/security checks, artifact checks, and clean-Mac manual-install test — not on Developer ID signing or notarization.)*

**Accept:** On a clean, unmanaged Mac with no developer tools: download DMG + checksum → verify checksum → drag to Applications → complete Apple's **Open Anyway** flow → onboard → first explicit-action rewrite in < 3 minutes. The release notes must accurately state supported CPU architectures and warn that managed Macs may block an unidentified app.

## Stage 4.5 — Launch checklist (production privacy/AI checks reopened)

- [ ] All PRD §8 success metrics measured and met. *(Instrumentation exists, but the criteria are not attestable as "met" from this sandbox — there's no live dogfooding data here, and CLAUDE.md's own current-state note already says Stages 3.3-3.5 haven't been visually verified. What's now measurable: **first-streamed-token latency** — `ActionEngine` logs `firstTokenMs` on the first delta of the single-variant streaming path (the 3-variant path wasn't instrumented per-variant to avoid log noise for a secondary metric). **Per-app AX success rate** — Settings → Reliability now shows a live "Per-app reliability" table sourced from `CompatibilityMap.snapshot()`, percentage highlighted below the PRD's 90% target. **Daily usage / ≥60% acceptance** — already covered by the Usage tab since Stage 3.5. **Icon-appears-<150ms** — not separately instrumented: the keystroke→icon-show call chain (`EventTap.onKeyDown` → `FocusMonitor.handleKeystroke` → `OverlayController.showIcon`) is fully synchronous on the main thread with no network/async hop, so the only variable cost is the AX frame read inside `pollFrame()` — structurally fast by construction, but not measured with a hard number.)*
- [x] Privacy copy and behavior agree: text leaves the Mac only after explicit user action. *(Passive typing now only drives local icon state. Recommendation classification starts after the user explicitly opens the action menu; all other inference remains behind action/Analyze/validation buttons.)*
- [x] Excluded-by-default list shipped: password managers, banking apps. *(New: `AppRuleStore.seedDefaultExclusionsIfNeeded` seeds `AppRule.excluded = true` for the most common macOS password managers (1Password, Bitwarden, LastPass, Dashlane, Keeper, Apple Passwords, Keychain Access) on first launch, same idempotent one-time-seed pattern as the existing tone defaults. "Banking apps" deliberately not app-listed: banking access is almost entirely browser-based with no fixed bundle ID to seed, and login/PIN fields there are already covered regardless of site by the existing secure-field detection (Golden Rule #3) — documented as a deliberate scope decision, not silently dropped.)*
- [x] Production-safe AI transport selected and integrated. *(V1 is BYO Azure OpenAI: the user supplies endpoint, deployment names, and their own Keychain-stored key. No WriterFlow account, shared credential, remote membership database, or custom WriterFlow API.)*
- [x] Production credential and destination hardening. *(Release builds compile out `.env` / `secrets.env` credential reads and bootstrap; requests accept only HTTPS Azure Responses URLs on `*.openai.azure.com` / `*.cognitiveservices.azure.com`; upstream error bodies are not surfaced or logged.)*
- [x] Public cost/pricing UI disposition. *(Retained as editable estimates of the user's own Azure spend, with explicit copy that WriterFlow never bills them. V1 disables three-call parallel generation and makes one provider request per action.)*
- [x] Remote config production disposition. *(`RemoteConfigFetcher` and its arbitrary URL Settings surface were removed.)*
- [x] Backlogs separated: multi-language/offline grammar/Windows remain v1.1 product ideas; Developer ID/notarization/Sparkle and accounts/membership/remote databases/licensing are explicitly v2.0 in `ROADMAP.md` and `RELEASE.md`.

## V2.0 deferred — outside Phase 4 acceptance

The following are deliberately not Phase 4 task boxes and do not block v1:

- Apple Developer Program membership and a Developer ID Application certificate.
- Developer ID signing, notarization (`notarytool`), and ticket stapling. `scripts/release.sh` and `WriterFlow.entitlements` are retained as future workflow scaffolding.
- Sparkle 2, a hosted appcast, EdDSA update signing, and automatic updates. V1 updates are manual.

## Post-v1 compatibility release

Version 2.0.2 replaces the current-release ARM64-only packaging constraint with one
universal arm64+x86_64 executable while preserving the v1 ad-hoc signing, manual
Gatekeeper, and manual-update policy. `make compatibility-build` compiles both macOS
14.0 slices; `make verify-release` verifies the universal app and mounted DMG. The
historical Stage 4.4 statements above continue to describe the published v1.0.0 artifact.
